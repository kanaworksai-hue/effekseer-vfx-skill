# 诊断案例

三个前后对照教训，每个都是**重建的单类 A/B**：把随附示例在某一类问题上改回一个已知的失败版本，两个版本在本技能默认的胶囊
Lab 中用相同的 seed、镜头和绝对帧号渲染，真实的帧只做了裁切、缩放和排版。出处（两次采集的 evidence ID 和帧 hash）见
[case_images/cases.json](../../../skills/effekseer-vfx/references/case_images/cases.json)。失败本身来自这些效果的早期迭代；
图片是新的渲染，不是当时的历史画面。

案例绝不能替代对你的构建运行 `vfx effect-verify`。先说出可见的问题，再选一类修法；不要把最终参数照搬到每个效果里。
选择与当前最差项匹配的案例：白团 → 爆炸；拖尾退场 → 飞行体；参数写了但形状不变 → 护盾。要复现一个案例，先 `vfx examples add`
对应示例，做出 BEFORE 的改动，`vfx review`，再撤销改动并再次 review：第二轮会把同样的对照写成 `<ID>_compare.png`。

## 火焰爆炸：一直不退的白色接触

![火焰爆炸：接触持续过久（before）与随附的 3 帧接触（after）](../../../skills/effekseer-vfx/references/case_images/fire_contact_residue.png)

**BEFORE：** Detonation flash 存活 14 帧而不是 3 帧，Fire core 存活 22 帧而不是 5 帧，Fireball 的 ramp 一直保持白色到寿命的
55 %，而不是在 12 % 就转为橙色。**看 f18。** BEFORE 仍是一整块白色圆盘，遮住了火球的形状和目标；AFTER 已经冷却成带热中心的
橙红色主体，因此饱和的形状、碎片和不对称的甩出都能读出来。f42–78 几乎相同：问题只出在接触上。lint 会对 14 帧的闪光给出警告
（`contact should be 2-5`）；连拍说明了原因。

| 可见问题 | 先检查 | 第一类修法 | 再看哪里 |
|---|---|---|---|
| 闪光之后仍是一团白 | 闪光和核心的寿命、主体颜色 ramp、emissive、重叠的 Add | 缩短接触；让主体的高亮段更早交给橙红色 | 主体轮廓能否在接触之后保留（f12–18） |
| 火焰退场后只剩小亮点 | 主体的实际寿命、火 → 烟的交接 | 让一个有体积的火或烟层承担中段 | f18–42 的形状变化 |
| 尾段空白，或灰烟像没画出来 | 序列提前播完、灰度值与背景相比 | 对齐播放片段、ramp 和寿命，保留可见的烟 | 逐帧看 f54、60、66，以及结束后的清空 |

每轮只改一类。不要把所有尺寸和所有 emissive 乘以同一个系数。

## 飞行体：随头部一起消失的拖尾烟

![飞行体烟尾：拖尾烟太短（before）与随附的拖尾（after）](../../../skills/effekseer-vfx/references/case_images/projectile_tail.png)

**BEFORE：** Smoke trail 存活 14–18 帧而不是 38–42 帧，烟雾图集以每格 2 帧播放而不是 4 帧，duration 是 1.0 s 而不是 1.2 s。
两版的飞行都是 0.45 s，所以头部在同一帧到达。**看 f27、f39 和 f54。** f27 时 BEFORE 的路径起点已经没有烟，而 AFTER 在施法者附近
仍有灰烟；f39 到达之后，BEFORE 在目标处只剩几缕红色丝状笔触，而 AFTER 沿路径保留一条断续的灰色烟线，它一边漂移一边变薄，直到 f54。
帧按绝对时间对比，而不是压缩到不同 duration 的相同百分比。

| 你看到的 | 可能原因 | 第一类修法 |
|---|---|---|
| 头部到达，整条拖尾在同一帧消失 | 跟随式继承、立即停止或实例很短 | 先检查 `inherit=TRAIL`（`WhenCreating`）和释放，再看寿命 |
| 粒子还活着但纹理已经是空白 | 图集在寿命结束前就播完了 | 调整 `frame_length` 和使用的帧范围 |
| 白色和橙色都在，烟还是看不见 | Blend 灰色太接近背景 | 在默认舞台上提高到合适的中间调，保留冷却过程 |
| 拖尾粗得像管子 | 发射太密，每层宽度和寿命都相同 | 拆分主尾、细尾和脱落粒子；再去掉多余的发射 |

"拖尾实例仍然存活"和"玩家仍能看到烟"是两种不同的说法。根据图案变化、材质和运动来判断，而不是根据粒子数量；
只加长 `duration` 只会多出一段空白尾段。

## 护盾：始终不露出间隙的破碎

![护盾破碎：只用 cutoff（before）与彼此分离的球面碎片（after）](../../../skills/effekseer-vfx/references/case_images/shield_breakup.png)

**BEFORE：** 去掉了六片 `shell_fragments`，于是破碎只靠壳的 alpha cutoff 曲线，而这条曲线写入和回读都是正确的。
**看 f81、f90 和 f96。** BEFORE 中球在 f84 还是完整的，到 f86 就消失了：没有任何一帧露出间隙，只有几片碎片飞出；它是被关掉的。
AFTER 在 f80 把壳交接给六片真实的球面碎片，它们带着可见的间隙分开、向外翻滚、颜色衰减，到 f108 已经消失。

| 你看到的 | 先检查 | 可行方向 |
|---|---|---|
| 曲线回读正确但没有出现洞 | 这种 Model + 材质 + 插件组合的真实画面 | 如果这种组合不会侵蚀，交接给分段的弧或真实的球面碎片 |
| 碎片突然出现，而且更大更亮 | 碎片的 emissive、颜色和出生重叠 | 让整个壳退场成碎片；限制它们的高亮时间 |
| 到 `duration` 时仍能看到大碎片 | 最后一次出生、寿命和颜色曲线 | 更早开始 RGB 衰减，留出清空的余量 |
| 碎片看起来粘在表面上 | travel、spin 和真实的空间方向 | 先分开，再减速；带一点翻滚，不要均匀整齐的径向扩散 |

在最初的迭代中，几何间隙先成立了，但 f108 时仍残留大碎片，独立评审仍然给出 iterate；又一轮调整了碎片寿命和 RGB 衰减，完成了退场。
加入新形状不能成为忽视最后一帧的理由。这次失败只说明这种壳材质组合不会可见地侵蚀 —— 并不说明 Model 层从不支持 alpha cutoff ——
而且修复保留了官方渲染器。

## 使用案例

把案例中的检查问题写进简报的验收条件，再用你自己的标准连拍和素材验证。基本方向来自 [layering](layering.md)、[timing](timing.md)
和 [skeletons](skeletons.md)；案例只是补充有证据支撑的诊断。
