# 検証済みのエンジン規約（Effekseer Core 1.80.7 + EffekseerForGodot4 1.80.5.1）

以下の各項目は、実際のレンダーで確認したものです。そのまま使い、軸、単位、ブレンドの挙動を推測し直してはいけません。
新しい規約を確認したら、計測方法と一緒にここへ追記してください。

目次：角度と軸 · 力とモーション · メッシュとフレネル · テクスチャとフリップブック · 継承とライフタイム ·
ゲーム入力と動的方程式 · レンダリング、HDR、Lab · アンカーと配置 · コンパイラの拡張

## 角度と軸

- **Ring の角度**：0° は上、90° は左を指し、反時計回りに増えます。スイープする弧をアンカーの中心に置くには、
  スイープの中央に対してリングの中心をオフセットします。
- **Sprite の Z 回転** は反時計回りです。ペイント系の形状の向きを目測してはいけません：`vfx texture-info <name>` は、
  カバー率、バウンディングボックス、縁への接触、主方向、三日月の膨らみの方向を同じ規約（+x が 0°、反時計回り）で報告します。
  レシピには実測した角度を使います。例：`T_Slash02` の膨らみは 108° と計測され、`slash_set()` は `SLASH02_BULGE = 105` を使います。
  このテクスチャを差し替えたら、計測し直して定数を更新してください。
- **`billboard='Billboard'` は Z 回転を無視します**（`rotation=[0,0,90]` のスプライトも直立したまま）。ロールが必要なスプライトは
  既定の `RotatedBillboard` を使います。
- **`rotate=True` の球の放出**：パーティクルのローカル +Y が外側を向くので、`travel.end=[0,d,0]` は外へ飛び、
  負の値は内側へ引き込みます。
- **`rotate=True` の円の放出（既定は Y 軸）は異なります**：Core は `Translation(r,0,0)*RotationY(angle)` を組み立てるので、
  ローカルの **+X** が外側を向き、+Y は上のままです。床に沿って転がり出る煙には `travel.end=[[d0,d1],0,0]` が必要で、
  `[0,d,0]` にするとまっすぐ立ち昇る柱になってしまいます。`rotate=False` では変位はワールド方向になります
  （立ち昇るパーティクルにはこちらを使います）。
- **`rotate=True` の球の放出は PVA の `velocity` も回転させます**：`velocity=[0, v, 0]` は上ではなく、各パーティクルのランダムな
  生成方向へ飛びます。そのように放出した煙の柱は横へ流れて沈みました（レビューの `sinks` フラグ）。
  `spawn=dict(shape='Sphere', radius=[...], rotate=False)` なら `velocity` はワールド方向のままです。
- **軸固定ビルボード**：`billboard='YAxisFixed'` に `pivot='bottom'` を組み合わせると、原点からローカル +Y に沿って伸び、
  その軸を中心に回ってカメラを向くクアッドになります — 軸を真正面から見下ろす場合を除き、どの角度からでも太さを保つビームです。
  `DirectionalBillboard` は +Y をパーティクルの運動方向に揃えます。知覚できないほど小さな速度（1e-4 units/frame、
  `charge_chain`）を与えると、オイラー角なしで静止したスプライトを任意の点へ向けられます（計測：曲がった背骨上の 7 点の連なりで、
  アークがすべてのアンカーに届いた）。
- **`travel.end` は絶対的なローカル位置** であり、`position` からのオフセットではありません。また `rotate=True` の放出は
  そのローカル座標系も回転させます。床を転がる煙は、`position` を床の高さにした `renderer='None'` のピボットの下に置きます。
  ワールド方向の変位には `spawn rotate=False`（`spray`）を使います。

## 力とモーション

- **Drag が減衰させるのは力場で蓄積した速度だけで、PVA の速度は減衰させません。** 「弾けてから留まる」は、
  velocity + drag ではなく、EaseOut を付けた `travel` で作らなければなりません。
- **重力の単位は units per frame² です。** 落ちる火花は 0.001–0.002、岩は 0.004、立ち昇る煙は 0.0003–0.0006。桁が一つ大きいと
  パーティクルは画面外へ飛び出します（lint は 0.01 を超える値を拒否します）。
- **床との衝突 `collide`**：ワールド座標系で、`height` はワールドの高さです（Lab の床は 0.02）。高さ 1.35 m の着弾点から
  重力 0.0015 では 20 フレーム以内に床に届くものはないので、跳ね返りが意味を持つのは爆発、ボスの叩きつけ、着地するものだけです。
- **Track + Circle の `Order` 放出では螺旋になりません**：1 フレームに 1 セグメントずつ進むので、飛行速度ではピッチが引き伸ばされ、
  平らなジグザグになります。代わりに、ヘッドの周りにランダムな傾きの `wisps` のストロークを使います。

## メッシュとフレネル

- **プロシージャルな円柱と円錐** は、軸に沿って `DepthMin` から `DepthMax` までを占めます。`mesh()` はそれらを原点の上に立てます。
  **球** は正規化された -1..1 の奥行きを使います：サイズは Depth ではなく `scale_start` で決めます。
- **Cone は下を向きます**（底面が +Y 側の端にあります）。上を向いた結晶には `radius2≈0` の `Cylinder` を使います
  （`crystal()` はそうしています）。`Mesh/Divisions/X=6` で六角柱になります。`ShapeNoise/WaveNoisePower` は球を
  凸凹した液体の塊にします。大きな球は `rings ≥ 24` が必要で、そうでないとシルエットが角張ります。
- **プロシージャルモデルの V は上から下へ走ります。** スクロールするカラーテクスチャはタイル可能でなければならず（`T_NoiseStreak02`）、
  グラデーションはスクロールしないアルファテクスチャ（`T_GradientV01`）に入れます。そうしないとくっきりした継ぎ目が出ます。
- **Falloff**：`begin` はカメラに面した中心、`end` は縁で、`pow` を大きくすると `begin` の領域は **小さく** なります
  （赤/緑のテスト：pow 8 では球のほぼ全体が `end` を示す）。細く明るいリム（フレネル、衝撃シェル）には `pow` 0.25–0.5 を使います。
  球の前面だけを描くには `culling='Front'` を使います（Effekseer の命名：`Front` は前面を表示。`Double` は内側の裏面も
  縁として光らせ、球が中身の詰まったものになります）。シールドは縁を光らせ、柱は縁を透明にします。
- **カラーテクスチャ、または常時カットオフ + エッジを持つ Model レイヤー** は、Godot プラグインではシェル球の上で灰色のまだらとしてレンダーされます。
  平坦な色 + フレネルを使い、ディゾルブは効果切れの時だけにします。目に見える崩れには、シェル全体にカットオフをかけるのではなく
  `shell_fragments`（実際のジオメトリ）を使います。
- ブラックホール、闇の球、チャージに **カメラを向く「渦ステッカー」は使いません**：`orbit_band` で傾いた平面上にリングを置き、
  描画順に積み重ねます — 奥の半リング → コア（Blend の黒い円盤または明るいコア）→ フォトンリング →
  手前の半リング — こうすると手前の半分がコアの前を通ります。プラグインは **エフェクトレイヤー間の ZWrite を無視します**
  （深度を書き込む球と深度テストするリングの組み合わせは効果がありませんでした）。遮蔽はリストの順序だけで決まります。リングの表面を回すには、
  Z 回転ではなく `alpha_scroll` を使い、筋がリングに沿って流れるようにします。

## テクスチャとフリップブック

- **UV ディストーションのテクスチャは不透明な RG オフセットマップでなければなりません**（`T_Distort01/02`）。アルファ上の白いマスクを
  ディストーションマップとして使っても、何も歪みません。
- **アルファテクスチャはアルファチャンネルを読みます**。`T_Noise*` のマスクはどれも `cutoff` のディゾルブにそのまま使えます。
- **ディゾルブのしきい値は Easing でないと動きません。** Godot の描画で計測しました（EffekseerForGodot4 1.80.5.1、Lab と
  Mobile レンダラーのゲーム）。`AlphaCutoffParam/Type = FCurve`（Percent でも Time でも）のしきい値は寿命の間ずっと最初の
  キーのままで、形は侵食されません。`Type = Easing` なら動き、カーブの形はイージングの種類（`Linear`、`EaseInQuadratic`、
  `EaseInCubic`、`EaseInQuartic`、`EaseInQuintic`、`EaseOut*`）で決まります。Core は開始・終了しきい値を 0..1 に丸めるので、
  「保ってから侵食する」形は負の開始値ではなく ease-in で作ります。コンパイラは常に Easing を書きます。正確に制御するなら
  `cutoff=dict(start=a, end=b, easing='EaseInQuadratic')`、カーブ `[[percent, value], ...]` を書けば最も近いイージングに
  当てはめます（`cutoff_easing`）。読み戻しだけでは分からないので、ストリップを見てください。
- **フリップブックの整数**：`flipbook.frame_length`、`x`、`y` は Core の整数プロパティで、正の整数でなければなりません
  （4.5 はネイティブで拒否され、その前にフィールドのバリデータが捕まえます）。再生を長くするには、整数のフレーム長とライフを一緒に延ばします。
- **フリップブックに UV ディストーションをかけない**：`distortion_intensity` はテクスチャ全体の UV で測られるので、4×4 シートで 0.12 は
  セルの半分ずれて隣のフレームをサンプリングします — 炎が縁のくっきりしたブロックに切り刻まれます。lint が拒否します。
  ディストーションが必要なら単一フレームのテクスチャを使います。
- **フリップブックシート**：画像生成モデルは、使える連続性を持った 4×4 の連番全体（1024²、セル 256²）を作れます。
  `vfx process-texture <original> <output> --size 1024 --grid 4 4` で処理します：セルは位置を保ち（クロップも再センタリングもしない。
  すればアニメーションががたつく）、各セルの縁はにじみを防ぐためにフェザーされます。
  `frame_length` ≈ life / 16。単発は `loop='Once'`、ループする炎は `Loop` とランダムな開始フレームで。
- **爆発シート一枚、レイヤー二枚**：加算の炎（ランプ：白 → 黄 → オレンジ → 暗い赤 → 消える）と、約 8 フレーム遅らせた
  Blend の暗い煙のレイヤー。煙は炎より **前にリストし**（炎の奥に描く）なければなりません。そうしないと火球に黒い穴が開きます。
- **侵食の縁の色** は冷めた赤の上に加算されます。黄色っぽい縁はオリーブ色になります。炎には `scaling≈2` で `(255,80,15)` を使います。
- **ウィスプの筋のテクスチャ**：ペイントされた筋の帯を、幅いっぱいのまま行方向にクロップし（横方向にタイルできるように）、
  アルファ = 輝度で 512×256 にリサイズします。既定の中央寄せ処理は左右に余白を加え、タイリングを壊します。

## 継承とライフタイム

- **継承**：Core の既定の `LocationEffectType` は `Already`（毎フレーム親に追従）です。`WhenCreating` は
  誕生時にだけ親のトランスフォームを取るので、ハンドルが動いてもパーティクルはその場に留まります — 飛翔体のトレイルはこれに依存しています。
  `renderer='Track'` は一つのレイヤーの連続したインスタンスを繋いでリボンにします。`WhenCreating` と組み合わせると
  途切れないトレイルになります。
- **`EffekseerEmitter3D.stop_root()`** は新しい放出を止めます。既存のパーティクルは自分のライフを全うし、その後で
  `finished` が発火します。
- **子のタイミング**：子の生成は、親インスタンスの死亡ではなく生成から計時されます。`renderer='None'` の親は子を回転させられ、
  `travel` で中心へイージングする子は螺旋状に落ち込みます。
- **ランダムなサイズにはカーブを付けられません**：ランダムな `size` / `scale_start` の範囲と `size_curve` / `scale_curve` の組み合わせは
  コンパイルに失敗します（コンパイラはカーブに固定の開始スケールを掛けるため。lint が拒否します）。サイズを変化させるには
  2 つ目のレイヤーを使います。

## ゲーム入力と動的方程式

- **`bind` は Godot プラグインで実行時に機能します。** 動的方程式（`@O.y = @In0`）を持つ Fixed の位置やスケールは
  毎フレーム再計算されます：再生中のハンドルでプローブが `@In0` を 3 → 9 → 5 と変えると、ビームの長さと先端のフラッシュは
  2 フレーム以内に追従し、エミッターを回転させると狙いが変わりました。コンパイラは方程式を `Core.Dynamic.Equations` に書き込み
  （同一のコードは共有される）、save/open の後にそれらを確認します。
- **新しいハンドルは .efk の入力の既定値（レシピの `inputs`）から始まります**：最初のシミュレーションフレームで、kaiju ビームの
  着弾点のしぶきが実際の終点ではなく既定の 160 m の位置に出ました。そのため `Vfx.play()` / `Vfx.beam()` はハンドルを作った直後に
  入力を送り、`CombatVfxHandle` はその後も毎フレーム送り直します（初期のプローブで 0 になったのは、その .efk に既定値が保存されて
  いなかったためです）。
- **保持する本体**：ビームの本体は、長寿命のインスタンス一つではなく `held()` のクロスフェード（interval ごとにインスタンス一つ、
  ライフ 2×interval、フェードはそれぞれ interval 一つ分）なので、`release()`（`stop_root()`）で時間どおりに終わります：ストリップでは
  怪獣のビームは解放から約 15 フレーム以内に細くなって消え、`TestApi.gd` は解放したビームが自身を解放することをチェックします。

## レンダリング、HDR、Lab

- **スクリーンディストーション `material='BackDistortion'`** は Godot プラグインで機能します（`hint_screen_texture`）。`distortion` は
  強さです（0.4–1.2）。屈折させるのは不透明なオブジェクト（床、ダミー）だけで、他のエフェクトレイヤーは屈折させません。暗く無地の
  ステージでは床のリングとダミーの縁にしか現れないので、フレームを拡大して確認してください。ディストーションをオフにしても
  エフェクトは成立していなければなりません。
- **Lab のステージと HDR ブルーム**：既定のステージはライティングされた深いスレートブルーです（背景 `1a2433`、床 `1d2733`、
  環境光 0.75、キー 1.5、フィル 1.0）。Forward+ では、プラグインの加算 / エミッシブ出力は HDR バッファに入ります。
  ライティングされた代役キャラクターで計測したところ、ダミーのハイライトのピークは約 3.4× だった一方、エフェクトのコアは 8× を超えたため、Glow は
  `smoothstep(threshold, threshold + hdr_scale)` で 2.8 から立ち上がり 6.0 で完全にオン、intensity 1.5、strength 1.1、
  トーンマッピング前に加算、5 段階のブラー 1.0/1.0/0.85/0.6/0.35、コアが早めに白く焼けるよう Filmic white 4、
  `glow_bloom=0` としています。これらの数値はライティングされたトゥーン調の代役キャラクターで計測したもので、既定の Lab のカプセルのダミーでは
  まだ計測し直していません。しきい値は出発点として扱い、ステージの明るさ、ダミーのライティング、代役を変えたら、しきい値を動かす前に
  ダミーのピークを計測し直してください（リニアトーンマップ、露出 1/8 で読み戻す）。
  `godot --path vfx/godot -- --no-glow` は比較用にポストプロセスを無効にします。レシピのプリミティブ
  `glow()` はテクスチャレイヤーであり、この HDR ポストプロセスではありません。ステージを変えたら総覧全体をレンダーし直します。
- ブルームが強いと、接触が正当に白熱しているエフェクトはピークのフレームで `washed out` を報告します。それは
  1〜3 フレーム続くだけなので、ストリップで判断し、フラグを黙らせるためだけに接触を弱めてはいけません。
- **ソフトパーティクル `soft` は Forward+ で機能します**（EffekseerForGodot4 1.80.5.1、Godot 4.7.2）。プラグインのシェーダーは
  `hint_depth_texture` をサンプリングし、不透明な深度の手前 `soft` ワールドユニットにわたってパーティクルをフェードさせます。Lab の床に
  半分沈めた深度テスト付きのカードで計測しました：`soft` なしでは床の線で明るさが 1 ピクセル以内に 206 から 81 へ落ち、
  `soft=0.3` では約 9 ピクセルにわたって 198 → 188 → 169 → 124 → 81 と滑らかに変化しました。空中のカードは `soft` の有無にかかわらず
  まったく同じ色（216, 198, 155）を保ちました。パーティクルのサイズに近い `soft` はカード全体をフェードさせます（lint が警告します）。
  深度テクスチャに入るのは不透明なジオメトリだけです：煙を透明な水面に対して柔らかくするには、水面が深度を書き込む
  （または不透明な深度プリパスを持つ）必要があります。Compatibility レンダラーには深度テクスチャがありません：以前の Lab ではそこで
  `soft` がスプライトをほぼ完全に透明にしました — Compatibility では使わないでください。
- **スケール時のステージフラッシュ**：Godot のオムニライトは 1/距離 で減衰する（attenuation 1）ので、Lab はフラッシュのエネルギーに
  ステージのスケールの 2 乗ではなくスケールそのものを掛けます（2 乗にすると、怪獣のヒットでステージ全体が白飛びしました）。

## アンカーと配置

- Lab のアンカー：`body` は床から 0.95 m、`impact` は 1.35 m、`ground` は 0。`body` アンカーのエフェクトの床レイヤーは
  約 `y = -0.93`、`impact` アンカーのエフェクトでは約 `y = -1.3` に置きます。それより低く書くと、深度テストされるデカールは床の下に消えます。
- 打撃の線を横切る近接の衝撃リングには `tilt=(0,58,0)` を使います：左から右への攻撃に垂直で、
  パースでは縦長の楕円に見えます。

## コンパイラの拡張

レシピのフィールドは Effekseer の機能を厳選したサブセットです。エフェクトに、コンパイラにまだないエンジン機能が必要なときは：

1. その機能を持つ参照用ノードを作り（またはそれを持つエフェクトを開き）、プロパティパスを見つけます：
   `vfx discover` は新しいノードのすべてのパスを型と列挙値付きで `vfx/work/property_schema.json` に書き出し、
   `vfx core property-list <file.efkefc> node/root/0` は実際のノードのパスを一覧にします。
2. **書く前に読む**：`vfx core property-get <file> <path>` で現在の値を読み、`vfx core property-set <file> <path> <json>` の後に
   もう一度 `property-get` して、Core が実際に保存した値を確認します。カーブは `vfx core curve-list` / `curve-set`、
   レンダラーのパネルは `settings-list` / `settings-set` を通します。
3. 現在の Core が保存するプロパティだけを使います。インポート時にしか読まれない古いフィールドに頼ってはいけません。
4. その機能をレイヤーフィールドとして `scripts/effekseer_ai/authoring.py` に追加し（`vfx layer-schema` に現れなければなりません）、
