# モーションと経路

飛翔体では 3 つの役割を計画します：ハンドルに追従する **ヘッド**、ワールド空間に残される **トレイル**、そして経路からこぼれ落ちる
**振りまきパーティクル**。`sustain()` で放出し、トレイルは `inherit=TRAIL` で残します。到達時にゲームが `stop_root()` を呼ぶと、
それらは自然に消散します。ヘッドにははっきりした輪郭が必要で、トレイルは長さと明度で差を付けます。発射の瞬間の集中線や短いリングは、
見る人が速度を読み取る助けになります。

斬撃は、実際の平面とスイープ（`swing()` + `slash_arc`）で経路を見せ、弧に沿って二次放出を時間差で行います。
二次パーティクルはイージングした `travel` で速いから遅いへ移ります。Drag は PVA の速度を減衰させません
（[エンジン規約](engine-conventions.md) を参照）。`travel` を書く前に、回転後のローカル軸を確認してください：球と円の放出では
放射方向の軸が異なります。

ボリュームと経路は別々に診断します：トレイルが細いのは問題なくても、ヘッドがボリュームのない点になってはいけません。
飛翔体自身のストリップは到達で終わり、着弾は含みません。Lab の通常再生ではペア全体が表示されます。

モーションはスケールだけではありません。スイープ、侵食、UV フロー、回転するピボット、変形でメインの形を変え、
破片、煙、モートは属性の方向で組み立てます：氷は溜めてから砕け、闇は引き込み、炎は昇り、毒はゆっくり沈む — それぞれ連続したフレームで裏付けます。

ランタイムが提供するのは直線と放物線（`arc`）の経路です。曲線の経路、一斉射撃、持続するビームには、まずブリーフとランタイムの拡張が必要です。
このスキルにないツールや API が存在するとユーザーに伝えてはいけません。

## 速度を形とリズムに込める

| 見える問題 | 最初の確認 | 最初の変更 |
|---|---|---|
| 飛翔体が浮かぶボールに見える | 発射時に方向の変化と速度の担い手があるか？ | 後ろへ流れる短い風の線、方向のある火花、長さの異なるテール |
| トレイルがプラスチックのチューブに見える | 幅が均一で、色が平坦で、全レイヤーのライフが同じではないか？ | テクスチャに余白を与える。短く熱いテールと長く柔らかいテールを分ける |
| 火花が等速で漂う | `travel` は速いから遅いになっているか？ | EaseOut の後、重力か軽い動きに引き継ぐ |
| 斬撃がカメラの前のステッカーに見える | 実際の傾いた平面、スイープ、それに沿った放出があるか？ | まず平面とスイープを直し、それから弧に沿って細部を時間差で出す |
| 破片が規則的な花火に見える | 同じサイズ、同じ発生フレーム、球対称になっていないか？ | サイズとリズムに段階を付ける。主な動きをアクションの方向に沿って組み立てる |

速度の担い手は見る人が方向を読み取るためにあるもので、新しいパーティクル群である必要はありません。トレイルや形がすでにその役目を果たしているなら、
シンプルなままにします。属性が一時停止しても構いませんが、その停止ははっきりしたアクションに繋がらなければなりません：
氷の結晶は成長を止めてから砕け、闇のエネルギーは集まってから解放されます。

角度の範囲を揃えても、明るいパーティクルと暗いパーティクルは一致しません。ジオメトリのペアは固定パラメータを使います。
モーションのずれは [layering](layering.md) の手順で診断します。煙の残像は意図的に別のリズムで動かしても構いませんが、そのことをブリーフに書きます。
