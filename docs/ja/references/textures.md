# テクスチャの役割、生成、受け入れ

役割を選び、プロンプトを書き、それから生成します。**複雑なペイント系の形状** — 煙、斬撃の弧、炎の本体、亀裂、氷、シンボル — は
**画像生成モデル** で作ります。**数式で作る形状** — グロー、リング、ノイズ、グラデーション、トレイルの帯、RG ディストーションマップ — は
プロシージャルテクスチャです（`vfx procedural` で再生成できます。名前は [primitives](primitives.md) にあります）。`vfx init` は、
プリミティブが既定で使う 7 枚のペイント系テクスチャのスターターセット — `T_SmokeSheet01`、`T_ExplosionSheet01`（4×4 シート）、`T_WispTrail01`、`T_Smoke02`、`T_Explosion01`、
`T_Crack01`、`T_IceShard01` — とそのプロンプトもインストールします。`vfx examples add` は、それを使うサンプルと一緒にさらに 4 枚（`T_Impact01`、`T_Slash02`、
`T_Rune02`、`T_Vortex01`）をインストールします。スキルの `assets/examples/texture_prompts.json` には、同梱していない一般的なペイント系の形状の
プロンプトのひな形もあります（斬撃の三日月、炎の舌、稲妻、ルーンの円、氷の棘、炎のシート…。`source` にその旨が書かれています）：
一つを `vfx/texture_prompts.json` にコピーして手直しし、生成して処理します。ペイント系の形状を Python で描いて真似してはいけません。

## 生成

- ホストが画像生成ツールを提供しているなら、書いたプロンプトでそれを使います。手を加えていない出力を
  `vfx/textures/generated/<T_Name>.png` に保存します。
- 提供していない場合は、**何も代用しません**：プロンプトを `vfx/texture_prompts.json` に追加し、どの画像を生成すればよいか
  （名前、サイズ、プロンプト）とどこに保存するかをユーザーに伝え、その画像を必要としない部分の作業を続けます。
- すべてのプロンプトを `vfx/texture_prompts.json` に `{"id": "T_Name", "size": 256, "prompt": "..."}` として記録します（シートには
  `"grid": [4, 4]` を、既定以外の処理には `"post"` を追加）。プロンプトが記録されていないペイント系テクスチャは lint が拒否します。
- 原画を上書きせずに、ゲーム用テクスチャへ処理します：
  `vfx process-texture vfx/textures/generated/T_Name.png vfx/textures/processed/T_Name.png --size 256`
  （`--color` は色をストレート RGBA のまま保持します。フリップブックシートには `--grid 4 4 --size 1024` を使い、セルの位置を保ちます）。
- 計測：角度、膨らみ、はみ出しは `vfx texture-info T_Name`。縁、アルファ、小サイズでの残り方、フレームの変化は `vfx texture-audit T_Name --role shape`
  （または `flipbook --grid 4 4`、`trail`、`symbol`、`light`、`uv_distortion`、`screen_distortion`）。監査の `preview` 画像を開いてください。

サイズ：通常のパーティクルは 128–256、メインの形と紋章は 512。検証済みの 4×4 連番は 1024² です。

## プロンプトの内容

視覚的な役割、輪郭と内部構造、必要な余白、背景または透過のモード、除外するもの（環境、キャラクター、文字、UI は不要）、
目標サイズを明記します。マスクの場合：純黒の上に白い形。連番では、グリッド、成長から崩壊への変化、一定の中心とスケール、
すべてのセルの余白を明記します。ループでは、最初と最後のフレームが繋がることを明記します。

塊のある形には読み取れる輪郭と変化のある太さが必要で、余白を持った非対称でも構いません。光にはコアからの滑らかな減衰が必要で、
対称でも構いません。紋章やシンボルは正確な幾何形状と密な装飾を使って構いません。煙は目標のスタイル — くっきりした外縁、
内部の明度、または柔らかいボリューム — に従いますが、すべての煙を漫画的な綿の玉にする必要はありません。
光学的な星形や紋章そのものに「ルールを崩す」を当てはめてはいけません。

| 種類 | 具体的に指定すること | 避けること |
|---|---|---|
| 斬撃と爪痕 | 主方向は一つ、根元は太く先は細く、途切れと不均一な太さ、弧の内側の空間 | 幅の均一な三日月のアイコン。等間隔の爪の線 |
| バーストと塊のあるフラッシュ | 重みのあるコアと方向のある縁。コアは完全に詰まっているか、はっきりリングになっている | 中央にランダムな小さな穴があり、目や顔に見える |
| 煙と土埃 | はっきりしたスタイル、輪郭と内部の明度、大きさの異なる房、段階的な崩壊 | 同じ形の綿の玉。輪郭のない灰色のグラデーション |
| 光と星 | 滑らかで熱いコア、まっすぐな減衰、役割で選んだ対称性 | 光を曲がった途切れ途切れのストロークにして、巨大なグローで救済する |
| 紋章とシンボル | はっきりした密度、構造の階層、細かなシンボルの帯 | 数文字の巨大な文字が縮んで空のリングになる |
| 地面の亀裂 | 衝撃点から枝分かれし、根元は太く先は細く、局所的に不規則 | 均一な格子やタイル状のセルが床のタイルに見える |

穴埋めして使える依頼の例（煙のテールの連番）：

> 目的：炎の飛翔体の後に残る灰色の煙の残滓。連続した 4×4 の連番、1024²。塊は濃い状態から始まり、上へ巻き上がりながら、
> 次第に不揃いな断片へと崩れていく。中心とスケールは一定、すべてのセルに余白。内部の明度を保ち、外側の輪郭は重なり合うように。
> 規則的な丸い煙の玉や均一な放射状の広がりは避ける。キャラクター、環境、文字、UI は入れない。ゲーム内で色付けする独立したアセット。

これはテンプレートであって、生成済みアセットの出所記録ではありません：生成後は、実際のプロンプト、原画、処理設定を記録します。
紋章、斬撃の弧、炎の本体には、色を変えるだけでなく、それぞれの役割を書く必要があります。
`assets/examples/texture_prompts.json` にはサンプルテクスチャのプロンプトが入っています。

## 受け入れ

ハードエラー：ファイルの欠落、無効なグリッド、グリッドで割り切れない寸法。最初や最後のセルが空、フレームの保持は意図的な場合があります。
中間セルの空き、飛び、重複はヒントにすぎません — 画像を見てください。フルサイズで美しい細いテクスチャも、標準カメラでは消えることがあります：
64 px と 32 px のプレビューと実際のレンダーを確認します。

ここで実測済み：フリップブックへの UV ディストーションは隣のセルをサンプリングします（lint が禁止しています）。カラーテクスチャとアルファテクスチャは
異なるチャンネルを使います。UV ディストーションには不透明な RG マップが必要で、スクリーンディストーションはアルファで範囲を持たせても構いません。
炎には、クリップアート風の炎スプライトではなく、侵食を伴う検証済みの爆発連番を使います。

## 連番は変形しなければならない

セルを一つずつ見ていきます：形はあるキーポーズから別のキーポーズへ — 開く、巻く、裂ける、侵食される — と移っているか？
同じ輪郭を拡大しながら不透明度を下げるのは変形ではありません。濃い状態から崩れた状態への変化は速くても構いませんが、
見えるサイズに達した瞬間に本体がくずになってはいけません。

一つの連番を複数の役割で使う場合は、開始セルと再生速度を変え、その理由を書きます：熱いヘッドは濃く短い区間だけを再生してもよく、
煙のテールは色が先に冷めながらゆっくり変化させてもよい。
`frame_length × cell count` が再生時間で、life はインスタンスの寿命です。両者が異なる場合は、早期の退場、保持、カットを説明します。

小さなプレビューは一つのふるいにすぎません。テクスチャが 32 px で消えるなら、まず役に立つ見える線を太くし、無駄なディテールを取り除くか、
実際のレイヤーサイズを変えます。512 の原画をむやみに 2048 に上げてはいけません — 同じカメラでは、解像度を上げても画面占有率は変わりません。
