# ボリュームと遮蔽

まず本体のボリュームを決めます：氷の棘は結晶、柱はプロシージャルな円柱、衝撃波は傾いたリングか薄いシェル、降着円盤は
奥の半リング + コア + 手前の半リングです。カメラを向くスプライトは、フラッシュ、煙、カメラに向くべき形のために取っておきます。
標準カメラと任意のクローズビュー（`vfx review --view close`）で確認しますが、ライブラリのベースラインは標準の対戦演出のままです。

ここで実測済み：球の奥行きは円柱とは扱いが異なります（球のサイズはスケールで決める）。Cone の先端方向は推測してはいけません
（結晶は端の半径を指定した Cylinder を使う）。Model レイヤーは ZWrite に頼れないので、遮蔽はリストの順序に従います。
Fresnel の `begin`/`end` と `pow` は、名前から想像される通りではなく、[エンジン規約](engine-conventions.md) に記載された通りに振る舞います。

大きなシェルや柱を、半透明の中身の詰まったドームにしてはいけません。まず輪郭、内側の透明度、キャラクターの視認性を確認し、
明るさはその後です。全画面のグローで形の問題は隠せません。暗いコアは既定のステージで読み取れなければならず、明るい背景（`--bright`）でも確認します。

既存の Ring、Model、UV スクロール、ディゾルブの機能を優先します。カスタムメッシュは後回しのアセット経路です：まずどのプリミティブでも
その形を表現できないことを示し、次にエクスポート、UV、リソースがパッケージと一緒に運ばれることを検証します。
未検証の前提を回避するために公式レンダラーにパッチを当ててはいけません。

## 標準カメラでボリュームを選ぶ

| メインの形 | ここで使える構成 | 確認すべき空間関係 |
|---|---|---|
| 斬撃 | 傾いた Ring を持つピボット、または平面固定の弧 | 弧がアクションの点を通り、内側に空間がある |
| 爆発 | `billow`、昇る本体、傾いた波、地面の物質 | 着地点と高さがある。手前と奥のレイヤーが分離している |
| 暗いコア | 奥の半リング、コア、手前の半リングをこの順で | 手前の半分がコアの前を通り、奥の半分はコアに隠れる |
| 氷の結晶 | 先端のある六角柱、破片、冷気 | 先端の向きと面の光が異なる。砕けが明るい点の集まり以上になっている |
| 持続するシェル | フレネルの輪郭、表面の動き、破片での退場 | 内側のキャラクター、シェルの表面、背景がそれぞれ読み取れる |
| 光の柱 | 円柱、静的なアルファグラデーション、スクロールする筋 | 上下が自然にフェードする。本体を貫く UV の継ぎ目がない |

標準カメラでは、低い地面のリングは細い線に見えることがあり、クローズアップで美しいディテールも戦闘距離では消えることがあります。
表面のテクスチャを足す前に、横方向か上方向のボリュームを作ります。クローズビューは問題を見つける助けにはなりますが、
スケールの判断で標準カメラの代わりにはなりません。

レイヤーが前後に重なる場合は、まず描画順を整え、それから画像で確認します。すべての破片の手前に描かれた完全なシェルの輪郭は、
現れるはずの隙間を再び塞いでしまいます。炎の手前に描かれた黒い煙は、残るべき高彩度の本体を隠します。ジオメトリが正しくても、
順序のせいで間違って見えることがあります。
